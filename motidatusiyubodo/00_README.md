## 適用時の注意

- **2〜4 は、日曜 10:12 の週次棚卸しをまたがずに続けて行う。** 2・3 が済んで 4 がまだの状態で週次棚卸しが動くと、古い手順7のまま report.md が昔の形で丸ごと書き直され、作り手にページ全体の作り直しを頼むことになり、データの箱の仕組みが崩れるおそれがある。間に合わないときは、2 を始める前の状態（1 だけ済み）で止めておく。
- 1 だけを先に入れるのは問題ない（今の仕組みのまま、report.md の各プロジェクトの行に正本と日付が付くようになる）。
- 新しい数字は作らない。改修のときに箱に入れる数字は report.md（2026-11-22 10:12 時点）の現物から写す。「尺度プロンプト言語比較」の「140試行・成功24」は古い可能性が分かっているが、改修では直さず、次の週次棚卸しで正本から入れ直される。それまでの間、カードには「正本は未確認（2026-11-22 転記）」と出る（わざとそう出す設計）。
- 改修で見た目が少し変わる箇所：定期タスクのタブの中身（一覧 → トラッカーへの案内と無効化中のジョブ）、監視フックの説明文の「どちらも1日1回チェックします。」が消える、メモリーのカードの「約1割超過」が「約12%超過」になる（数字を手で書かないため、計算で出す言い方にした）、424行の「1つ」が「ひとつ」になる、プロジェクトのカードの下に正本と日付の注記が増える。本人に見せるときは、この点をひとこと伝える。
- 01 の文面にある `{適用日}` は、差し込む日の日付に置き換えてから貼る。それ以外の `{…}` はジョブが実行時に埋める部分なので残す。
- 01 の追加1では、正本の行に日付が無いとき「日付なし」と書く。02 の改修の後（追加3）は、同じ場合を sourceAsOf "未確認" とする（ページの注記の出し方をそろえるため）。
- 01・02 に載せた確認用の Python の手順は、見本の文字列で動作を確かめてある。本物のファイルで使えるのは、改修（と report.md の書き換え）が済んでから。
- 02 に書いた index.html の行番号は 2026-11-23 時点（576行）のもの。適用前に 02 の A-2 で、まだ合っているかを確かめる。

## 判断の記録（検収用）

- 単発タスクと監視フックのタブは残した。トラッカーの3つの欄（予定・進行中・定期ジョブ）には、この2つの一覧が無く、二重にならないため。
- 今回の棚卸しメモの「毎日動く定期タスクは9本」の本文にある、ジョブの名前を並べた括弧書きも外すことにした。一覧をトラッカーに一本化する趣旨に合わせるため。
- 対応するゴールが無いプロジェクトは、MEMORY.md §4 を正本とした（手順8が進行中の欄の正本を MEMORY.md §4 としているのに合わせた）。
- メモリーの各節の要約（開いたときの文）もデータの箱に入れた。箱の外に残すと、毎週の差し替えのたびに要約だけが古くなるため。その分、週次棚卸しが要約を書く手間が増える。
- 件数・合計・割合・曜日は箱に書かず、ページ側で数える・計算する形にした（同じ数字を2か所に書かないため）。メモリーの「合計」は節の字数を足した値（11,079字）ではなく、ファイル全体の字数（11,203字）であることを依頼文に明記した。
