## 依頼文ここから

Space「車候補リスト」（slug：che-hou-bu-risuto）の改修をお願いします。次の A〜D の4点を**1回の改修でまとめて**実装してください。最後の「移行」の節に書いた値以外、既存の車のデータ（価格・維持費込み cost*・下落 drop*・状態・格付け・注意点・区分・初回確認日・最終確認日）は変えないでください。

### 前提
- データは cars テーブル（server/src/schema.ts）。操作は listCars／addCar／updateCar（server/src/actions.ts）。毎日の巡回ジョブと AI エージェントが addCar／updateCar を呼び、利用者は画面の編集フォームからも updateCar を呼びます。
- 金額はすべて万円・小数第1位。
- 「今日」は日本時間（Asia/Tokyo）の日付。
- 以下、状態（status）が「掲載中」「値下げ」「要確認」の車を「**掲載中扱い**」と呼びます。
- 既存の呼び出し方（updateCar に carId と変えたい項目だけを渡す）は、この依頼で明記した場合を除いて、そのまま動くようにしてください。新しい項目はすべて省略可です。

### A. 入力時の確認（サーバー側。addCar と updateCar の両方。画面の編集フォームも updateCar を通るので同じ確認がかかる）

**A-1 新しい項目 costBasisMan（試算の総額。実数、null 可）**
- 意味：維持費込み・下落の試算に使った総額が支払総額と違う場合（ナビ後付け約10万円を足した「実質総額」で試算した場合など）だけ入れる。null のときは priceMan と同じ扱い。
- addCar・updateCar で受け付ける（省略可。updateCar で null を送ると消える）。priceMan より小さい値は受け付けない。
- listCars で返す。カードの想定コストの表の下に、costBasisMan があり priceMan と違う車だけ「試算は総額◯◯.◯万円（ナビ後付けなどを含む）で計算」と小さく出す。

**A-2 確認の規則**（n＝3・5・10、ケース＝Std・Cautious）
- **規則1（下落の上限）**：drop{n}{ケース} ≦ 基準総額 ÷ n ＋ 0.05。基準総額 ＝ priceMan と costBasisMan の大きいほう（costBasisMan が null なら priceMan）。
  - 0.05 は小数第1位への丸めの誤差を許す分。
  - **維持費込み cost* にはこの上限をかけない。** 10年では維持費の合計が売却額を上回り、正しい値でも総額÷年数を超えるため（例：車両ID AU7391428176 の cost10Std 28.6 は 186.8÷10＝18.68 を超えるが正しい）。
- **規則2（維持費込み ≧ 下落）**：cost{n}{ケース} ＋ 0.1 ≧ drop{n}{ケース}（同じ年数・ケースの2つが両方数値のとき）。
- **規則3（標準 ≦ 慎重）**：drop{n}Std ≦ drop{n}Cautious、cost{n}Std ≦ cost{n}Cautious（両方が数値のとき）。誤差の許容なし。
- **規則4（12項目はそろえて送る）**：1回の要求で cost*・drop* の12項目のうち1つでも送るなら、12項目すべてを送る（すべて数値、またはすべて null）。addCar も同じ（12項目すべて省略、すべて null、またはすべて数値）。12項目を1つも送らない updateCar（価格だけ、状態だけ、確認日だけ等）は規則4の対象外。

**確認をかける範囲**
- addCar：追加する行の全体。
- updateCar：更新後の行（既存の値に今回の変更を重ねたもの）のうち、**この要求で値が変わる項目**（送られた項目と、A-3 で自動調整された項目）にかかわる規則だけ。この要求で変わらない項目の既存値が規則に合わなくても、それを理由に拒否しない（確認日だけの更新などが、ほかの項目のせいで弾かれないようにするため）。
  - 規則1：変わった drop。priceMan か costBasisMan が変わったときは、すべての drop。
  - 規則2・3：組の片方でも変わったら、その組。

**拒否のしかた**：何も書き込まずにエラーを返す。エラー文は日本語で、どの項目がどの規則に反したかと数値を入れる。反した規則が複数あれば全部並べる。例：
- 「drop5Std（89.3）が上限（基準総額182.5÷5＝36.50）を超えています。下落は年あたり（総額÷年数）の値を入れてください。」
- 「cost5Std（26.4）が drop5Std（89.3）より小さくなっています。」
- 「drop3Std（33.0）が drop3Cautious（32.5）より大きくなっています。」
- 「cost・drop は12項目をそろえて送ってください（送られたのは cost5Std, cost5Cautious のみ）。」
画面の編集フォームは、このエラー文をそのまま「保存できませんでした：」の後に出す（今の作りのまま）。

**A-3 価格が変わったときの既存の試算の自動調整**
- updateCar で priceMan が今の値から変わり（差が0.05未満なら変わっていないとみなす）、その要求で cost*・drop* を送っていない場合、サーバーが既存の12項目を自動で調整する：
  新しい値 ＝ 小数第1位に四捨五入（既存の値 ＋（新しい priceMan − 古い priceMan）÷ n）。null の項目は null のまま。
  - 理由：年あたり負担 ＝（総額 − 売却額 ＋ 維持費）÷ 年数 で、価格の改定は総額だけを変える（売却額・維持費は変わらない）。だから値上げでも値下げでも「差額÷年数」だけ動くのが正しい。
  - costBasisMan が入っている車は、costBasisMan も同じ差額だけ動かす（ナビ後付けなどの上乗せ分は変わらないため）。
  - 四捨五入は 0.05 を切り上げる方式。浮動小数の誤差対策として「10倍して 1e-9 を足してから Math.round し、10で割る」。
  - 例：車両ID AU7238356203（今 164.9万円）を 162.9万円に値下げ → drop3Std 17.1→16.4、drop5Std 11.3→10.9、drop10Std 10.4→10.2、cost5Std 19.8→19.4（他の8項目も同じ式）。
- 要求で12項目を送った場合は、送られた値をそのまま使う（自動調整しない）。
- 自動調整のあとで A-2 の確認をする。

**A-4 試し実行（dryRun）**
- updateCar に省略可の dryRun（真偽値）を足す。true のときは A-2・A-3・C・D の処理をすべて行ったうえで**何も書き込まず**、{ ok: true, dryRun: true, preview: 更新後の車1台（listCars の1台分と同じ形） } を返す。規則に反すれば通常と同じエラー。
- dryRun でないときの応答は今までどおり { ok: true }。

### B. 最終確認日の自動表示

**B-1 上部の表示**
- 「最終確認日：2026年11月14日」の固定の文字をやめ、データから出す。
- 表示：「最終確認日：YYYY年M月D日」。値は、掲載中扱いの車の lastChecked のうち最も新しい日付。掲載中扱いの車が0台なら全車の lastChecked の最新。車が1台もなければ「—」。
- その後ろに小さく「（掲載中の車を巡回で確かめた日のうち最新）」。

**B-2 古い車が混ざっていることを見せる**
- 各カードの「年式／走行距離／初回確認」の並びに「最終確認」（M/D 表記）を足す。
- 掲載中扱いの車で、今日（日本時間）と lastChecked の差が**3日以上**なら、その日付を警告色にして「（◯日前）」を添え、カード上部の札の並びに「確認が古い」の札を出す。売約・候補外の車には出さない。
- 上部の最終確認日の下に、該当が1台以上あれば「掲載中のうち◯台は確認日が3日以上前です」と出す。
- 「3日」はプログラムの中で1か所の定数にしておく。

### C. 格付けの理由の札と、並び替えの基準

**C-1 新しい項目 gradeReasons（理由の札。文字列の配列、既定は空配列）**
- 値は決まった一覧からだけ選べる。今の一覧は「**保証短い**」の1種類。一覧にない文字は受け付けない（表記ゆれを防ぐため）。将来増やすときは一覧に足す。
- 「保証短い」の意味：支払総額（基本プラン）に含まれる保証が1年未満（1ヵ月・3ヵ月など）。
- addCar・updateCar で受け付ける（省略可。updateCar では送った配列で丸ごと置き換える。重複は1つにまとめる）。listCars で返す。
- 画面の編集フォームに「保証短い」のチェックボックスを足す（保存時に gradeReasons として送る）。

**C-2 カードの札**（掲載中扱いの車だけ。売約・候補外の車には理由の札を出さない）
- 格付けの札の右に、次の順で小さな札を並べる。本命の車には理由の札を出さない。
  1. 自動の札（データ不要）：格付けが候補・様子見で、cost5Std が 32 を超える →「5年負担32万円超」、30 を超え 32 以下 →「5年負担30万円超」、cost5Std が null →「未試算」。
  2. gradeReasons の札（「保証短い」など）。
  3. 格付けが候補・様子見なのに 1 も 2 も出ない車 →「理由未記入」（目立たない色）。
- 格付けの札の近くに「5年・標準 年◯◯.◯万円」（cost5Std）を小さく出す。null なら出さない。
- 「格付けの表示」の説明文を次に変える：「格付けは5年・標準の年間負担で決めています。本命＝年30万円以下かつ保証が短くない車、候補＝年32万円程度まで、様子見＝それ以外。売約・候補外の車は格付けにかかわらず表示します。」

**C-3 並び替え**
- 「想定コストが安い順」の基準を、3年・標準から**5年・標準**に変える（「維持費を含む」表示では cost5Std、「車両の下落だけ」表示では drop5Std）。表示名を「想定コスト（5年・標準）が安い順」に、説明文の「3年・標準」を「5年・標準」に変える。3年／5年の切り替えは作らない。
- 未試算の車は末尾、同じ値なら支払総額の安い順（今と同じ）。

### D. 初回価格・現在価格・価格改定の記録

**D-1 新しい項目**
- firstPriceMan（初回価格。実数）：最初に確認したときの支払総額。addCar で priceMan と同じ値を自動で入れる。updateCar では変えられない（要求の項目に入れない）。
- priceHistory（価格改定の記録。JSON の配列、既定は空）：各要素は { date: "YYYY-MM-DD", fromMan: 改定前, toMan: 改定後 }。古い順。
- priceMan はこれまでどおり「現在の支払総額」。
- listCars では、上の2つに加えて次の値を返す：lastPriceChange（最後の改定 { date, fromMan, toMan, kind: "値下げ" または "値上げ" }。無ければ null）、lastDropOn（最後の値下げの日付。無ければ null）、updatedAt（更新日時、ISO 形式の文字列）。

**D-2 自動記録**
- updateCar で priceMan が今の値から変わったとき（差が0.05未満なら変わっていないとみなす）、priceHistory の末尾に1件足す。date は、要求に priceChangedOn（新しい省略可の項目、YYYY-MM-DD）があればそれ、無ければ同じ要求の lastChecked、それも無ければ今日（日本時間）。
- 同じ値の priceMan を送っただけなら記録しない（画面の編集フォームは毎回 priceMan を送るため）。
- firstPriceMan は何があっても変えない。値上げも値下げも同じように記録し、kind は差の正負で決める。

**D-3 状態「値下げ」の扱い**
- 価格の動きは D-1 の項目で表すので、状態（status）は掲載の状況だけを表すことにする。状態の値の一覧から「値下げ」は消さない（古い呼び出しが送ってきても受け付ける）が、画面では「値下げ」の車を「掲載中」と同じに扱う。
- 編集フォームの「状態」の選択肢と、絞り込みの「状態」の札から「値下げ」を外し、絞り込みに「値下げあり」（掲載中扱いで priceMan ＜ firstPriceMan の車）を足す。
- 上部の集計：「掲載中」の欄は状態が掲載中または値下げの台数、「値下げ」の欄は「値下げあり」（同じ定義）に変える。

**D-4 カードの見せ方**
- 支払総額の下に、改定が1件以上ある車だけ「初回 166.9万円 → 11/16 値下げ ▲2.0万円」のように出す（値上げは「＋4.0万円」）。改定が2件以上なら「（改定◯回）」を添え、押すと全件（日付・改定前→改定後）を開く。
- 値下げは目立つ色、値上げは控えめな色。

## 2. 設計の判断と理由（検収者向け。依頼文には含めない）

### (a) 入力時の確認
- **規則1だけでは取り違えを見逃すことがある**：総額を入れてしまっても「総額＞総額÷年数」になるのは「売却額 ＜ 総額×(1−1/年数)」のとき。3年は売却額が総額の2/3以上だと見逃す（デリカミニは3年売却148.1／総額189.8＝78%）。ただし10年はほぼ必ず引っかかり、6項目のどれか1つでも反すれば全体を拒否するので、実際には検出できる。さらに**規則2（cost ≧ drop）**は、年あたりの cost（ID39の5年26.4）と総額（89.3）の比較になるので、取り違えをほぼ確実に捕まえる。両方入れる。
- **規則3（標準≦慎重）**：慎重は売却額に下位25％点（中央値以下）を使うので、必ず標準以上。標準と慎重の取り違えを捕まえる。今のデータで反する車は0台（写しで確認）。
- **規則4（12項目そろえて送る）**：ID2（維持費込みだけ計算し直して下落を取り残した）と ID35（5年の維持費込みだけ直した）の型の取り残しを、送る側の段階で防ぐ。
- **価格だけ変わるとき（A-3 の自動調整）**：拒否にすると、画面の編集フォーム（価格は直せるが試算は直せない）で価格を直せなくなる。黙って古い試算を残すと ID35 の型になる。価格の改定は総額だけを変えるので、差額÷年数で動かすのが計算上正しい。丸めの積み重ねで最大0.1程度ずれうるが、売却額自体が参考値（n＝2 のセルなど）なので許容範囲と判断。正確な値が要るときは巡回が12項目を送れば上書きされる。
- **costBasisMan**：ナビ後付け込みの実質総額で試算する車（ID38・42）は、10年の売却額が10万円未満の車種（ノート・ルークスなど）だと、正しい下落でも「支払総額÷10」を超えうる。誤って拒否しないための項目。表示上も「どの総額で試算したか」が分かる。
- **丸めの許容（0.05／0.1）**：小数第1位に丸めた値どうしの比較なので、規則1は0.05、規則2は両方の丸めで最大0.1ずれるので0.1。規則3は丸めで大小が入れ替わらないので許容なし。既存データでは ID13・18・27・30 が「ちょうど0.05」の境目で切り下げ側に丸まっている（02 の D）。
- **入れなかった確認**：
  - 「cost − drop（＝年あたり維持費）が一定の範囲」：正しい車でも8〜14万円とばらつき、ID2 の取り残し（4.4）も「3〜20」のような範囲では捕まらない。役に立たないので不採用。
  - 「drop ≧ 0」：売却額が購入額を上回る（値上がり）こともありうるので不採用。
  - 「本命なのに保証短い」を拒否／格付けの自動化：GOAL.md の基準どおりにするなら矛盾だが、本人が例外として決める余地を残すため、拒否はせず札で見せるだけにした。

### (b) 最終確認日
- 定義を「掲載中扱いの車の lastChecked の最新」にしたのは、売約・候補外の車の確認日は更新されなくて当然で、混ぜると意味がぼやけるため。
- 各カードの確認日と「3日以上前」の印は入れる（推奨を採用）。巡回は毎日なので、1日抜けても印は付かず、2日続けて抜けたら分かる。04 の追記が入るまでは多くの車に印が付くが、それが実態。

### (c) 札
- 注意点の文章から作る案は不採用。表記が「1か月」「1ヵ月」「1ヶ月」「3か月と短い」「3ヵ月／3,000km（販売店保証）」とゆれており、ID38・42 のように「販売店保証1ヵ月だがメーカー保証付き納車も可（一般3年）」と長短が同じ文に並ぶ例もあって、文字の拾い出しでは誤判定する。データとして持ち、巡回が判断して入れる形にした。
- コストの理由（30万円超・32万円超）は cost5Std から機械的に出せるので、データに持たない（取り残しが起きない）。
- 移行の14台：点検報告の10台（候補なのに5年値が本命水準）に加え、事実として保証が短い4台（ID4・6・17・20）も入れた。ID4 は注意点が空だが、`files/実質コスト試算_2026-11-14.md` 98行目に「保証が3か月と短い」とある。各車の出典は notes_for_review.md。

### (d) 価格の記録
- priceMan をそのまま「現在価格」として残すので、巡回など既存の呼び出し側は変更なしで動く（後方互換）。
- 移行は作り手が新しいマイグレーションで入れる（前例：0004 で格付けの初期値を UPDATE 文で入れている）。もちが操作で入れる案は、初回価格を後から書き換えられる操作を作ることになり、誤用の余地が増えるので不採用。
