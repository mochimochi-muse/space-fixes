## 2. いま何が重くなりうるか

### 分かっていること
- **一覧を開くと、全部の相談の本文をまるごと受け取る形です。** DATA-PLAN.md に「list_sessions の要約に search_text（相手＋モデル＋題名＋すべての本文を、Markdownの記号を外して1つにつなげたもの）を入れる」とあります。画面の検索はこれを使って、画面側で行っています。今は一覧を開くたびに、本文の合計（約11万字）とほぼ同じ量の文字を受け取っていることになります。
- **絞り込み（相手・モデル・期間）と並べ替え（新しい順・古い順・やり取りの多い順・タイトル順）も、画面側で全件に対して行っています**（DATA-PLAN.md）。サーバーは新しい順に並べて返すだけです。
- **search_text は、保存されていません。** テーブル定義（sessions と messages の2つ）に search_text の列はないので、一覧の求めがあるたびに、全部の本文を読み出して作っていると考えられます（作り置き・使い回しをしているかどうかは**未確定**）。
- **1件の相談を開くこと自体は軽いままのはずです。** get_session という操作があり、本文のテーブルには「相談のid・並び順」の索引（messages_session_idx）があるので、1件分の本文だけを取り出すのは件数が増えても速い作りです。
- データベースの大きさ（約360KB）は、それ自体は問題になる大きさではありません。重くなるとすれば「一覧のたびに全文を運ぶ・つなげる・画面で全文を探す」ところです。

### 分からないこと（未確定）

## 3. どう変えるか
考え方は「一覧は見出しだけ、本文は開いたときだけ、検索はデータ側で行って結果だけ返す」です。

1. **一覧（list_sessions）は見出しだけにする**
   - 返すもの：id、日付、時刻、相手、モデル、メモ、題名、URLの有無、やり取りの数（「やり取りの多い順」の並べ替えに使うため）。
   - search_text（本文全部）は返さない。
2. **本文は、その相談を開いたときだけ受け取る**
   - get_session（今もある操作）で、その1件の本文だけを受け取る。画面がすでにそうしているなら、ここは変更なし（**未確定**なので作り手に確かめてもらう）。
3. **検索はデータ側で行い、当たった相談だけを返す**
   - 新しい操作（例：search_sessions）を足す。渡すのは検索の言葉、返すのは当たった相談の id の一覧（できれば、当たった箇所の前後の短い抜き出しも）。
   - 検索のきまりは今と同じにする：空白で区切った言葉が**全部**入っている相談（AND）、大文字・小文字を区別しない。探す範囲は相手・モデル・メモ・題名・本文。
   - 今と同じ結果にするため、検索用の文字列（Markdownの記号を外してつなげたもの。大文字・小文字をそろえたもの）を、相談を追加・修正したときに作って保存しておき、検索ではそれを探す形を勧めます。既存の相談には、一度だけまとめて作る。削除のときは一緒に消す。
   - 大文字・小文字のそろえ方は、データベースの機能（SQLite の LIKE は英字しかそろえない）にまかせず、保存するときと探すときで同じそろえ方をプログラムで行う。
   - 全文検索の専用の仕組み（SQLite の FTS5 など）は、日本語の言葉の区切り方に注意が要るので、300件のころには勧めません。数千件になって、ふつうの探し方で遅くなってから考えます。
   - 検索欄に1文字打つたびに問い合わせるのではなく、打ち終わりを少し待ってから問い合わせる。
4. **変えないもの**
   - 絞り込み（相手・モデル・期間）と並べ替えは、見出しに対して今までどおり画面側で行う（見出しだけなら軽いため）。検索で当たった id で、さらにしぼる。
   - 02で決めた時刻不明の表示と並び、会話の見た目、Markdownの表示、「元のスレッド」へのリンク。
   - データ（相談・本文）の中身は一切変えない。
   - 一覧のページ分け（何件かずつ出す）は、300件のころには要らない見込みです。もっと増えたら別に考えます。

```python
"""軽量化の着手の合図を測る（AI相談ログ）。写したデータベースを読み取り専用で開いて数える。
使い方: python3 -I measure_size.py <写したapp.db>
"""
import sqlite3, sys
from pathlib import Path

p = Path(sys.argv[1]).resolve()
con = sqlite3.connect(p.as_uri() + "?mode=ro", uri=True)
n = con.execute("SELECT COUNT(*) FROM sessions").fetchone()[0]
m = con.execute("SELECT COUNT(*) FROM messages").fetchone()[0]
chars, nbytes, longest = con.execute(
    "SELECT SUM(LENGTH(body)), SUM(LENGTH(CAST(body AS BLOB))), MAX(LENGTH(body)) FROM messages").fetchone()
pages = con.execute("PRAGMA page_count").fetchone()[0] * con.execute("PRAGMA page_size").fetchone()[0]
print(f"相談: {n} 件（合図: 300件前後）")
print(f"本文: {m} 通、合計 {chars:,} 字（{nbytes:,} バイト）、いちばん長い1通 {longest:,} 字（合図: 合計60万字前後）")
print(f"データベースの大きさ: {pages:,} バイト（約 {pages/1024/1024:.2f} MB）（合図: 2MB前後）")
print(f"1件あたりの本文: 平均 約 {chars/n:,.0f} 字")
```
