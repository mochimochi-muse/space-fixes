# Sol確認：ギャラリー改修（Neon草案＋実ファイル確認へのレビュー）2026-11-23

- 相談先：Perplexity、モデル GPT-6.2 Sol。https://www.perplexity.ai/session/af0ca5c0-cbe4-479e-8ac2-d2f45c5e8701
- 結論：範囲を A（★永続化）＋B（データ集約）に絞る案は承認。固定キーは現行の動的生成を維持し、明示ID化と SERIES.group 統合は別改修に分ける。ただし受け入れ条件は草案のままでは不足で、順序付き全件比較と、旧版で保存した状態を新版で復元するブラウザテストを必須にする。

## 主な指摘（もちの要約ではなく、実施に効く要点の転記）
1. **照合は集合ではなく順序付き全件比較**：作品AとBの img を入れ替えても集合比較は通ってしまう。旧版ITEMS（初期配列＋push 2回適用後）を基準に、231件を配列順のまま全フィールドで比較する（プロパティ順は問わない。型・null・欠落の違いは保持）。buildItemKeys() の出力も配列で比較し、各キーが同じレコードを指すことを確認。SERIES 37件・GROUPSも比較。データの転記はAIにさせず、スクリプトで機械変換するのが望ましく、ビルダーには全体書き直しではなく限定差分を求める。
2. **固定キーは今回は維持**：ID化まで混ぜると、保存済み組み合わせ・下書き・URLハッシュの参照まで確認範囲が広がる。将来ID化するなら、新形式は別キー（gallery-queue-v3 等）に書き、対応表で変換し、旧データは切り戻し期間残す。
3. **★永続化は gallery-rated-v1（文字列配列）でよい**：旧★はメモリのみなので移行不要。復元は buildItemKeys() の後、実行時は Set 管理。rated[idx] の全参照箇所を作品キーに揃える。未保存・不正JSON・型違い・重複・存在しないキーを想定し、無効値は表示に使わず、読み込みだけで保存を書き直さない。保存失敗でもページ操作は続けられること。「使い方」の文言は「同じブラウザで、保存が利用できる場合は再読み込み後も残る」程度に抑える。
4. **データ集約は application/json を採用、GROUPS は現状維持**：データブロックは読み込み側スクリプトより前に置き、textContent を JSON.parse して既存の変数に渡す。シリアライズ時に `<` を `\u003c` に置換して `</script>` での途中終了を防ぐ。生成後のHTMLから再抽出・再パースして元データと一致を確認する。パース失敗を空配列でごまかさない。SERIES.group 統合は、GROUPS が表示順・表示名・系統内順序も担うため等価にならず、別改修。
5. **維持条項の言い換えと公開判定**：「削除・改変しない」ではなく「A・Bに必要な内部変更と説明文更新を除き、既存機能の操作・表示結果・保存互換性を変えない」。合格条件：旧ストレージの引き継ぎ（同一オリジンで旧版の状態を作り新版で復元。queue-v1 のみの環境での既存移行も）、★の付与→再読み込み→絞り込み→解除の往復、ライトボックスの代表ケース（原寸あり／なし、img null、キー共有作品）、ナビゲーション・UI（ハッシュ、戻る・進む、高速スクロールバー、目次、絞り込み、初回の新しい順、ビルダータブ、モーダル、狭幅・広幅）、コンソールとネットワークで新たな例外・404がないこと、作業記録JSONが公開成果物に含まれないこと。

（Solは細かすぎる傾向があるため割り引く前提だが、今回の指摘は機械照合とエスケープ処理など安く効くものが中心で、原則として取り込む）
