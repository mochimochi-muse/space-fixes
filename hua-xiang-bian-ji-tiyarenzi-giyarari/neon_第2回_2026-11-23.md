## 2. 「要確認」だった部分の確定値
### ① 作品データの持ち方と既存プロパティ
データは <script> 内で SERIES（37シリーズ）、ITEMS（3ブロックに分割された配列）、GROUPS（5系統と所属シリーズID配列）の3変数に分かれて定義されています。
SERIES のプロパティ：id, no, title, short, cover, meta, note、任意で org（"lab"）
ITEMS のプロパティ：s（所属シリーズID）, img（拡張子なしファイル名または null）, vol, title, badge, cat（"once" / "retry" / "special"）, desc, how, src、任意で org（"lab" / "user"）, missing（画像なし時の表示文）
GROUPS の5系統IDとメンバー数：staged（段階シリーズ・12）、compare（比較・境界実験・4）、lab（自主研究・6）、craft（技法・7）、story（ストーリー・8）の計37シリーズで過不足なく一致しています。

### ② 作品IDの形式（最重要の確定事項）
作品（ITEMS）に明示的な id プロパティは存在しません。明示的な id を持っているのはシリーズ（SERIES[].id："origin", "final" など）だけです。
img も一意キーには使えません（生成不可項目は img: null であり、final の B-1 と story の 場面5 はどちらも img: "b1" で重複しています）。
現行コードの固定キーは、buildItemKeys() が it.s + "::" + it.vol + "::" + it.title（完全重複時のみ ~2 等のサフィックス付与）で動的生成した文字列（itemKeys[idx]）です。

### ③ キュー・localStorage の保存方法
既存の localStorage キーはすべてハイフン区切りで5つ使われています。
・gallery-queue-v2：現行の場面キュー。保存値はオブジェクトではなく固定キーの文字列配列（例：["origin::元画像::列に並ぶ人々", ...]）。
・gallery-queue-v1：旧インデックス配列のキュー。v2 が無い初回のみ読み込み、変換後に removeItem で削除済み。
・gallery-combos-v1：組み合わせキュー（文字列配列）。
・gallery-combo-draft-v1：組み合わせビルダーの下書き（{ sel, custom }）。
・gallery-view-v1：カード表示モード（"compact" / "detail"）。

### ④ 画像パスと拡張子の規則
・サムネイル：assets/thumb/{cover または img}.jpg
・通常表示画像（ライトボックス初期・合成フォールバック）：assets/{img}.jpg
・原寸画像（ライトボックス拡大時・合成優先元）：assets/orig/{img}.webp

## 3. 草案 A〜D への修正差分
### A. 改修依頼文の修正ポイント
・依頼範囲を「未実装の2点＋付随整理」に絞る
実装済みのUI改修（冒頭縮小・5系統目次・絞り込みバー・タブ移設・遅延描画・原寸フォールバック・キュー固定キー化）を「新規実装」として依頼しないこと。
代わりに依頼文の冒頭に「現行コードの既存機能（高速スクロールバー #fastScroll、指示線アノテーション #lbAnnoBox、ライトボックスのホイール拡縮・ドラッグ移動、URLハッシュ同期、キュー・組み合わせビルダー・モーダル一式）は一切削除・改変せず維持すること」と明記してください。
・作品データ集約の具体指定（設計9）
3分割されている ITEMS（および SERIES / GROUPS）を、<script type="application/json" id="gallery-data">（または <!-- DATA_START --> 〜 <!-- DATA_END -->）の1か所に集約します。
ITEMS は既存のキー名（s, img, vol, title, badge, cat, desc, how, src, org, missing）を一切変えず、1作品＝1行のJSONオブジェクトとして並べる指定に変更します（将来の外部JSON分離が機械的に可能）。
任意改善として、SERIES の各要素に group: "staged" 等のプロパティを持たせ、GROUPS 側で members 配列を手動二重管理しない構造にすれば、今後のシリーズ追加漏れを防げます。
・★高評価の永続化と固定キー化（設計1の残件）
現行の rated[idx] および data-rate-for="' + idx + '" を廃止し、キューと同じ固定キー（keyOfIdx(idx)）と localStorage 保存（キー名：gallery-rated-v1、値は固定キーの文字列配列）へ変更するよう指示します。
あわせて modalUsage 内の文言「（このページを開いている間だけ保持されます）」を「この端末に保存され、次に開いたときも残ります」等へ更新するよう指定します。
（必要であれば）絞り込みバーまたはキューバーに「★高評価のみ表示」を追加するかを明記してください。

### B. キュー・★高評価の固定キー移行設計の修正ポイント
・スキーマの修正：前回の草案では gallery_queue_v2 に { version: 2, keys: [...] } を提案しましたが、実ファイルではすでに gallery-queue-v2 に string[]（固定キー配列）が直接保存されています。既存ユーザーの保存済みキューを壊さないため、string[] 形式とハイフン命名規則をそのまま維持してください。
・固定キー形式の判断（重要）：
現行の it.s + "::" + it.vol + "::" + it.title を維持すれば、既存の gallery-queue-v2 との100%後方互換が保てます（移行コード不要）。ただし、vol や title の表記を後から修正するとキーが変わって保存済みキュー／★高評価が外れる弱点があります。
もし将来を見据えて各作品行に不変の明示的 id（例："origin-01"）を付与するなら、gallery-queue-v2 を読み込む際に「旧キー形式（:: を含む文字列）を検出したら新 id へ自動変換して保存し直す」1ステップを挟む設計にしてください。今の改修で表記変更の予定がなければ、まずは現行の itemKeys 方式に★高評価を揃えるのが最も安全です。
・★高評価の具体的な書き換え箇所（実コード基準）：
var rated = {}; → RATE_KEY = "gallery-rated-v1" から配列読み込み→マップ ratedSet へ展開（queue と全く同じ構造）。
cardHTML()：data-rate-for="' + idx + '" → data-rate-for="' + key + '"。
renderSeriesCards()：rated[idx] → ratedSet[keyOfIdx(idx)]。
syncRateUI()・lbRate クリックハンドラ：r.idx → keyOfIdx(r.idx) に変更し、変更時に localStorage.setItem(RATE_KEY, ...) を実行。

### C. サムネイル生成スクリプトの修正ポイント
実ファイルの画像パスが assets/thumb/{img}.jpg で確定したため、前回のスクリプトのデフォルト設定を以下のように差し替えます。
・入力元（--src）：./assets（表示用JPGが置かれているディレクトリ）
・出力先（--dst）：./assets/thumb
・出力形式：WebPではなく JPEG（.jpg、品質 quality=78〜80, optimize=True, progressive=True） をデフォルトに変更（HTML側が .jpg 固定のため）。
・除外ディレクトリ：assets/ 配下に assets/orig/（原寸WebP）と assets/thumb/（出力先）が同居する構成のため、走査ループで orig と thumb の両サブディレクトリをスキップするガードを追加します（src_dir.glob("*.jpg") のように直下のみ対象にするのが最も安全）。

### D. チェックリスト・壊れやすい点の追加差分
・照合基準の修正：ITEMS には明示的 id がないため、改修前後の完全一致照合は 「総件数」および「itemKeys（s::vol::title）の集合＋img の集合」 で比較してください。
・退行チェックの追加：ビルダーに326KBのHTML全体を再生成させると、指示外の細部（#fastScroll、#lbAnnoBox の ClipboardItem Promise渡し処理、restoreFromHash 等）が劣化・欠落しやすいため、これらが改修前と同じく動作することを公開前チェックリストに追加してください。
・既存ストレージ互換テスト：DevTools上で既存の gallery-queue-v2（["origin::元画像::列に並ぶ人々"] 形式）、gallery-combos-v1、gallery-view-v1 を入れた状態で改修版を開き、すべて消えずに復元されることを確認してください。
