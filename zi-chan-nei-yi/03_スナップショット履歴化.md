## 1. 決めたこと

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 置き場 | `~/workspace/資産内訳_履歴.jsonl`（ブリーフの案のまま） | スナップショット（`~/workspace/資産内訳スナップショット.json`）と同じ場所・同じ名前の始まりで、並べて見つけやすい。変える理由が無い |
| 形式 | JSON Lines。1行＝1回の取得分の JSON | 追記だけで済み、1行ずつ読める |
| 1行の中身 | スナップショットと同じ欄 ＋ `recorded_at`（履歴に書いた時刻。日本時間、秒まで。例 "2026-11-29T09:20:03+09:00"）。移した1行目だけ、さらに `migrated_from`（"資産内訳スナップショット.json"） | 同じ日付を2回書いたときに、どちらが後か分かるように。移した行は、ジョブが書いた時刻ではないことが分かるように |
| 文字コード・書き方 | UTF-8（BOM なし）、行の終わりは改行1つ（LF）、1行の中に改行を含めない（文字列の中の改行は `\n` と書かれる。行区切りに見える特殊な文字 U+2028・U+2029 も ` ` の形にする）。欄は名前の順、区切りに空白を入れない | どの道具で読んでも1行＝1件になるように |
| 書き方の決まり | 追記だけ。既存の行は書き換えない・消さない。追記は `asset_history.py append` だけで行う（手で書かない） | 履歴が後から変わらないように。手書きによる壊れた行を防ぐ |
| 同じ日付が既にあるとき（再実行など） | 中身（recorded_at・migrated_from を除く）が同じなら追記しない。中身が違えば追記し、その日付は後ろの行を正とする（[注意] を出す） | 再実行で同じ行が重ならない。追記だけの決まりを守ったまま、取り直した値を残せる |
| 前回値の読み出し | 「今回の取得日より前の日付で、最も新しい行」（同じ日付が複数なら後ろの行）。`asset_history.py previous --before 今回の日付` | 同じ日に再実行しても、前回＝前の週になるように |
| 壊れた行があるとき | 直さない・消さない。読み出しのときは飛ばし、行番号を [注意] で知らせる。ファイルの最後が改行で終わっていない（書き込みが途中で切れた）ときは、改行を1つ足してから追記する（既存の行の中身は変えない） | 壊れた行を勝手に直すと元の値が分からなくなる。新しい行が壊れた行にくっつくのを防ぐ |
| スナップショット | **廃止せず、「最新の1件」として残す** | 下の 2. |

## 2. 資産内訳スナップショット.json を残す理由

- ページのデータ部分の差し替え（02 の手順4）は、作り手にこのファイルの中身を写してもらう形にしてある。確認スクリプト（asset_page_check.py）も、既定ではこのファイルと比べる。
- ほかに、このファイルを読んでいるもの（別のジョブ・ページなど）があるかどうかは分からない（**未確定**。今回は読んでよいファイルが限られていたため確かめていない）。消すと、もしあった場合に壊れる。
- 今の値を人が見るとき、1つの小さなファイルで済む。
- 2つの関係：**スナップショット＝履歴の最後の行から recorded_at・migrated_from を除いたもの**。ジョブは「スナップショットを上書き → `asset_history.py append` がそのスナップショットを読んで履歴に写す」の順で書くので、両者は必ず同じ中身になる（`asset_history.py check` で確かめられる）。
- 版2（下の 5.）は欄を足しただけで、今までの欄の名前・意味は変えていない。もし古い形を読んでいるものがあっても、足した欄を無視すれば今までどおり読めるはず（ただし、読んでいるものがあるか自体が未確定）。

## 4. 既存スナップショットの移行（もちがそのまま実行するコマンド）

今のスナップショット（2026-11-22 分）を、履歴の1行目にする。**00_README の順序表の1番目**。11/29（日）09:12 より前に行う（09:12 を過ぎると、今までのジョブがスナップショットを 11/29 分で上書きし、11/22 分の値はこのファイルからは消える）。

### 1) 履歴ファイルがまだ無いことを確かめる

## 5. 版1（移した1行目）と版2（その後の行）の違いの扱い

| | 版1（1行目、11/22 分） | 版2（11/29 分から） |
|---|---|---|
| schema_version | 無い（無い行は版1とみなす） | 2 |
| holdings の kind・accounts | 無い（金の口座数は name「…、2口座分合算」の文の中だけ） | 守り資産に kind、合算した銘柄に accounts |
| 集計外の項目 | missing・note の文の中だけ（「前回 ¥***」「-¥***」など） | excluded に構造化（id・name・status・value・last_known_value・reason） |
| missing・note | 金額を含む文 | メモ。金額は書かない |
| recorded_at | 移行した時刻（ジョブの取得時刻ではない） | ジョブが書いた時刻 |
| migrated_from | "資産内訳スナップショット.json" | 無い |

- 版1の行は版2に直さない（追記だけの決まりのため。また、版1の集計外の金額は文の中にしか無く、取り出すと読み取りの判断が入るため）。
- 比べるとき（前回との比較・見直しの判定）は、両方の行にある欄だけを比べる。版1が前回のときは、kind・accounts・excluded は比べない（02 の本文の「前回の行に無い欄は比べない」）。
- 11/29 のジョブは、前回の行が版1なので、kind・accounts・excluded に入れる内容を、その行の name・missing・note の文から読み取って引き継ぐ（02 の本文の「データの形」の最後の項目）。
- 版2の行を読む道具は、schema_version で形を見分ける。asset_history.py の previous・check は「版」として表示する。

## 6. 戻せない過去の値（未確定）

- スナップショットは毎週上書きされてきたため、11/22 より前の週（11/15 など）の値は、スナップショットからは戻せない。
- 例外的に、11/22 分の missing の文に「確定拠出年金の待機資金（前回 ¥***）」がある。これは「前回の取得では *** 円だった」という1つの値で、その前回が何日の取得かは書かれていない（**未確定**。11/15 かもしれないが確かめていない）。
- ほかの場所（メインチャットの過去の報告、マネーフォワード ME 側の履歴、Space の過去の版など）に 11/15 以前の値が残っているかは、**確かめていない（未確定）**。今回は読んでよいファイルが限られていたため。
- 見つかった場合に履歴へ足すかどうか・足し方（追記だけの決まりのもとで、古い日付の行を後ろに足してよいか、別のファイルにするか）は**未確定**。足す場合でも、`previous` は日付で選ぶので、古い日付の行を後ろに足しても前回値の読み出しは正しく動く。

## 8. asset_history.py（このフォルダに置いた補助スクリプト）

ブリーフの成果物の一覧には無いが、履歴の決まり（追記だけ・同じ日付・壊れた行・改行）を毎回同じに守るため、手書きではなくスクリプトで追記する形にした。移行（4.）とジョブの追記・前回値の読み出し（02）で同じものを使う。

- `append [--snapshot パス] [--history パス] [--migrated-from 名前]`：スナップショットを読み、履歴に1行追記する（書き込むのは履歴ファイルだけ）。
- `previous --before YYYY-MM-DD [--history パス]`：その日付より前で最も新しい行を表示する（読み取り専用）。
- `check [--snapshot パス] [--history パス]`：行数・読めない行・日付の一覧と、最後の行がスナップショットと同じかを表示する（読み取り専用）。
- 既定のパス：スナップショット `~/workspace/資産内訳スナップショット.json`、履歴 `~/workspace/資産内訳_履歴.jsonl`。
- 終了コード：0＝できた／1＝[問題] か [注意] がある／4＝実行できない（引数の誤り・書けない）。詳しくはスクリプトの冒頭の説明。
- 置き場を変えるときは、02 の本文の2か所（previous と append）も同じ場所に書き換える。
