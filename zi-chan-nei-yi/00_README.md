## 2. 適用の順序

週次ジョブは毎週日曜 09:12 JST（次回 11/29）。下の 1〜6 は、**11/24（月）〜11/28（土）のどこか1日に、続けて**行う。日曜の朝（ジョブの前後）は避ける。

| 順 | 何を | いつ | 道具 | 承認・補足 |
|---|---|---|---|---|
| 0 | 控えを取る：スナップショット（03 の 4. の 0)）と index.html（01 の A の 4.）の写しを backup/ へ | できるだけ早く。遅くとも 11/29 09:12 より前 | ファイル操作 | 読むだけの写し。11/29 09:12 に今までのジョブが 11/22 分を上書きするので、その前に残しておく |

| 2 | 出す前の確かめ（01 の A）：index.html とスナップショットの SHA-256、確認スクリプトで「データ部分なし・19か所」 | 同じ日 | ファイル操作 | どれか違えば 3 に進まない |

### 順番の理由（短く）
- **控えを最初に**：11/22 分の値はスナップショットにしか無く、11/29 09:12 に上書きされると戻せないため。
- **履歴の移行を Space 改修の前に**：ページにもジョブにも触れない独立の作業で、失敗しても消してやり直せる。新しいジョブ本文は履歴があることを前提にしている。
- **Space 改修をジョブ差し替えの前に**：新しいジョブはデータ部分の目印が無いページを更新しない（止めて報告する）ので、先にページを改修しておかないと、11/29 からページが更新されなくなる。逆に、今までのジョブのまま改修後のページを更新させると、ジョブが文章を作り直して差し込み口を壊すおそれがある。
- **ジョブ差し替えを 11/29 09:12 より前に**：差し替えが遅れると、今までのジョブが改修後のページを今までの手順（文章まで作り直す）で書き換えてしまうため。
- **全部を同じ日に**：改修後のページと今までのジョブ、または改修前のページと新しいジョブ、という組み合わせの時間を短くするため。

### 01（Space 改修）がうまくいかなかったとき
- 01 の C の手順で、改修前の内容に戻す。
- そのうえで 02（ジョブ差し替え）を出すかを決める：
  - 出す：ページは改修前のまま止まり（11/22 のまま、***円の食い違いも残る）、毎週「ページ未改修のため更新を止めた」と報告が来る。スナップショットと履歴は毎週たまる。次の平日に 01 をやり直す。数字のずれが増えない、安全側の選択。
  - 出さない：今までのジョブのままページが毎週更新される（数字のずれが起きうる今の状態が続く）。履歴は作られない（03 で作った1行目のまま）。
  - どちらにするかは、もちの判断（ここでは決めない）。
